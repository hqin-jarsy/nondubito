FUTURE ART IMPORTS (run commands from the repository root)

1. Retain the full-resolution originals OUTSIDE Git, in <archive>/<work-id>/.
   Review source licenses/attributions as before. Register the work and manuscripts.
2. Generate lightweight previews into a separate OUTSIDE-repository upload folder:

   python3 scripts/build_art.py --image-work WORK_ID \
     --originals-dir /absolute/offline/archive \
     --previews-dir /absolute/upload/art --prepare-only

3. Check staging files:

   python3 scripts/verify_art_images.py --work WORK_ID \
     --local-dir /absolute/upload/art

4. In Cloudflare: R2 > nondubito-images > Objects > art/ > Upload > Files.
   Upload only the new work's .webp files, at most 100 per batch. This keeps the
   art/ prefix exactly once; do not accidentally upload into art/art/.
   Wait for "All files were successfully uploaded" before testing public URLs.
5. Validate the actual public image bytes (network access + Pillow required):

   python3 scripts/verify_art_images.py --work WORK_ID

   All images must pass. If an image was requested before upload completed,
   a temporary cached 404 can persist: let it expire or purge those exact URLs,
   then verify again. Do not publish broken links.
6. Build, check and publish HTML via the normal Git workflow:

   python3 scripts/build_art.py
   python3 scripts/build_art.py --check
   python3 scripts/test_art.py

   The browser smoke test also allows images.nondubito.net. Offline tests check
   the complete object manifest and HTML references; the verifier checks remote
   bytes, dimensions and content type separately. Review before committing.

For replacements, prefer a new source filename/object key to avoid stale caches.
If keeping an existing key, purge that exact URL in Cloudflare and verify again.
Keep an offline copy of every uploaded image; R2 is serving storage, not your
only archival backup. Different future categories can use different prefixes.
