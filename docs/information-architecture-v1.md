# Non Dubito 信息架构蓝图 v1

状态：设计基准，不直接改变公开页面  
日期：2026-09-05

## 1. 这次整理要解决什么

Non Dubito 已经不再是一页向下滚动即可理解的小型随笔网站，而是一座包含原创哲学、日常问题、历史研究与跨媒介作品细读的多语言图书馆。内容增长本身是成功；当前欠缺的是一套与内容规模相称的找路系统。

这次整理的目标不是让所有读者看见全部内容，而是让不同读者迅速看见适合自己的下一步：

1. 第一次来的读者知道从哪里开始；
2. 带着明确问题来的读者能够搜索；
3. 没有明确目标的读者能够舒服地漫游；
4. 回访读者能够知道最近新增或修订了什么；
5. 进入一篇文章以后，读者能够理解自己在哪里、还能往哪里走；
6. 八种语言的读者面对的是同一座网站，而不是八套彼此失联的目录。

## 2. 当前基线

以下数字是技术口径，不等于独立文章数量；其中包含语言版本、系列首页、分类页及其他索引页。

| 项目 | 当前数量 |
| --- | ---: |
| HTML 文件 | 7,277 |
| `essays/` 下的 HTML 文件 | 7,252 |
| sitemap URL | 4,598 |
| 系列／分类 `index.html` | 696 |
| Library 大类 | 13 |
| Library 系列卡片 | 212 |
| 首页 `<section>` | 31 |

同时存在四个结构性问题：

- 首页仍然兼任完整目录，新增系列不断增加页面长度和选择压力；
- Library 是完整的，但 13 个大类和 212 个入口要求读者先理解本站的分类方式；
- 全站没有统一搜索，当前只有科幻小说书架提供局部搜索；
- 页面普遍有人眼可读的日期，却没有统一的结构化发布日期、修订日期与内容清单，因而无法可靠生成“最新更新”。

## 3. 设计原则

### 3.1 入口少，内部丰富

一级入口控制在五至六个；丰富性在进入 Explore、系列或文章后逐层展开。首页不再承担“证明本站内容很多”的任务。

### 3.2 导航按读者意图，而不只按文件目录

文件放在哪里是维护问题；读者为什么来是导航问题。二者可以不同。例如“寓言、古老故事、史诗传统”目前保留在 `essays/everyday/stories/`，但在 Explore 中应归入“文学、影视与叙事”，不必为了改善导航而搬动 URL。

### 3.3 一个内容身份，多个进入路径

每个系列只有一个稳定身份和 canonical URL，但可以同时出现在不同阅读路径中。例如《权力论》属于 SAE 理论，也可以被“理解现代权力”阅读路径引用。交叉展示不是重复建档。

### 3.4 搜索、浏览与推荐互不替代

- 搜索回答“我知道自己要找什么”；
- Explore 回答“这里有什么”；
- 阅读路径回答“我应该按什么顺序读”；
- Latest 回答“最近发生了什么”；
- 相关阅读回答“读完这一篇以后去哪”。

### 3.5 URL 稳定优先于目录洁癖

本轮默认不移动已发布页面，不批量改 slug，不因为新的展示分类而重排物理目录。必要调整使用新入口指向旧 URL；只有确定的重复内容或错误 URL 才单独制定重定向方案。

### 3.6 多语言版本是同一作品的不同版本

“一篇文章有八种语言”在 Latest 和 Explore 中应主要表现为一个内容身份加语言状态，而不是八条相邻的新内容。搜索结果默认只显示当前阅读语言，读者主动切换时才跨语言查找。

## 4. 读者任务与对应入口

| 读者的真实问题 | 首选入口 | 页面要给出的答案 |
| --- | --- | --- |
| “我第一次来，这个网站在谈什么？” | Start Here | 五分钟理解核心直觉，并得到一条继续阅读路线 |
| “我想找康德／AI／孤独／《索拉里斯》。” | Search | 语言正确、可筛选、标题优先的结果 |
| “我不知道找什么，但想看看。” | Explore | 五个清楚的大方向和少量编辑推荐 |
| “最近新增了什么？” | Latest | 新作、重要修订及语言状态 |
| “我想完整看一个系列。” | Series page | 顺序、进度、版本、导读和篇目 |
| “我刚读完，接下来呢？” | Article footer | 系列下一篇、同主题一篇、跨领域一篇 |
| “我想看所有东西。” | Library | 完整、稳定、可筛选的总目录 |

## 5. 一级导航

建议桌面端主导航为：

`Start Here · Explore · Latest · Search · About · Language`

站名／Logo 本身返回 Home，因此不再单列 Home。

调整建议：

- `Essays` 不再作为首页的同义词；
- `Library` 从一级导航移入 Explore 页面中的明确入口，并保留页脚入口；
- `Crede si vis` 作为宣言性内容，放入 About 下方或页脚；
- `SAE Theory` 与 `Substack` 作为外部目的地放入次级导航或页脚，并保留外链标识；
- Search 在桌面端显示文字或图标，在移动端保持可见，不能藏入多层菜单；
- Language 是工具，不是栏目，位置与样式在全站保持一致。

这是 v1 的推荐结构；在改公开导航前，需要通过桌面和手机线框图确认一次。

## 6. Home 的职责

首页是接待厅，不是仓库清单。建议固定为以下六段：

1. **Hero**：一句话说明 Non Dubito，并把 Start Here 作为唯一强主按钮；
2. **五扇门**：五个探索方向，每个只显示一句读者问题和一个入口；
3. **Latest**：最近六项，区分“新作”与“修订”；
4. **从这里开始读**：三至五条编辑策划的阅读路径；
5. **本期／本月推荐**：少量可轮换文章，不与 Latest 重复承担职责；
6. **Languages + Full Library**：语言入口和完整书库入口。

首页不再为每个系列各放一个独立 section。系列的持续曝光由 Latest、推荐路径和 Explore 承担。

## 7. Explore：五扇门

Explore 不是 Library 的缩写版，而是一张按读者兴趣绘制的地图。

### A. SAE 与哲学

包括：SAE Foundations、First Critique、方法论、认识论、价值论、权利论、权力论、战争论、道德律、法学、经济学、SAE 与西方哲学、SAE 佛学及其他理论接口。

入口文案应先说这些系列帮助读者回答什么，再显示理论名称。可提供“普通读者路线”和“理论深潜路线”。

### B. 日常生活

包括：关系、工作、亲子、自己、金钱、时间、社交、成长、冲突等结构系列。

这一门应按问题而不是按抽象术语组织，例如“怎样关心而不接管”“工作为什么会吞掉人的判断”“拒绝怎样才是真的”。

### C. 心灵、AI 与技术

包括：AI 与人、意识与生活、认识与自我、学习与认知、人工智能陪伴及相关技术哲学文章。

这里同时服务从现实 AI 问题进入的读者和从意识问题进入的读者。

### D. 历史、权力与文明

包括：凿构周期律诸系列、历史与人物、文明史、二战、美国总统、欧亚帝王、经济史，以及从 SAE 理论中交叉引用的权力、权利和战争路线。

理论系列仍保留在自己的 canonical 分类；本门通过策划路径引用，不另建副本。

### E. 文学、影视与叙事

包括：文学细读、科幻小说、日漫、武侠、电影、电视剧、游戏，以及寓言、古老故事和史诗传统。

进入本门后再按媒介分架；不要在五扇门这一层直接展示两百多部作品。

## 8. Library 的新职责

Library 保留为全量目录，服务已经知道本站结构或希望系统浏览的读者。

建议能力：

- 按五个一级方向分组，再展开现有细分类；
- 支持语言、媒介、主题、系列状态筛选；
- 支持只看“全语言”“英／简／繁”“原作语言”等版本状态；
- 默认折叠长列表，并记住用户上次展开的位置；
- 每个系列只显示一次 canonical 卡片；
- 显示作品数／篇数时，从内容注册表生成，不再手工在多个页面分别维护。

Library 的完整性很重要，但它不再是新读者理解网站的第一道门。

## 9. Latest 的内容规则

Latest 不是把 sitemap 按文件修改时间倒排。它记录的是编辑事件。

### 事件类型

- `new`：新文章或新系列首次发布；
- `revised`：内容有实质升级，例如 v2 重写；
- `expanded`：旧系列增加新篇；
- `languages`：增加重要语言版本，可作为次级动态，不挤占全部主列表。

### 展示规则

- 同一作品的八种语言只占一张主卡；
- 卡片显示日期、事件类型、所属系列、摘要和可用语言；
- 默认展示最近十二项，首页取前六项；
- 提供按月份归档；
- 小修字词、链接修复和机械格式调整不进入 Latest；
- `published_at` 与 `updated_at` 由内容注册表明确记录，不使用 Git mtime 作为公开日期。

## 10. Search 的产品要求

### 10.1 搜索范围

搜索应覆盖：

1. 文章标题；
2. 作品名、人物名、作者名；
3. 系列名与分类名；
4. 摘要与编辑关键词；
5. 正文。

排序时标题、作品名和系列名的权重高于正文偶然命中。

### 10.2 默认行为

- 默认搜索当前阅读语言；
- 可主动选择“所有语言”；
- 结果显示所在方向、系列、文章序号和语言；
- 同一 canonical 内容的不同语言默认合并或隐藏非当前语言版本；
- 没有结果时给出相近关键词和 Explore 入口，而不是空白页。

### 10.3 筛选项

v1 只保留真正有用的筛选：

- 语言；
- 五个一级方向；
- 内容类型：理论／日常／历史／文学／影视／游戏等；
- 系列或作品。

不要一开始加入过多哲学标签；标签需要编辑判断，过细会制造另一套难以维护的目录。

### 10.4 技术候选

Pagefind 适合纯静态大站，也支持语言与过滤。但 Non Dubito 当前同时存在：

- 英／简／繁共用一个 HTML、通过前端切换的页面；
- 每种语言拥有独立 HTML 的页面；
- 旧式语言频道和新式系列内语言目录。

因此不能直接把所有 HTML 全量索引后上线。应先建立 canonical 内容身份和语言版本映射，再决定使用 Pagefind 的 HTML 索引、生成独立搜索记录，或两者结合。

## 11. Series page 的统一结构

一个系列首页应稳定回答：

- 这是什么系列；
- 为什么值得读；
- 从哪篇开始；
- 是否必须按顺序；
- 一共有多少篇；
- 有哪些语言；
- 最近是否有重要修订。

推荐结构：

1. 面包屑；
2. 系列标题与一句话导读；
3. `从第一篇开始` 与 `任选一篇` 两个入口；
4. 篇目列表或分组；
5. 语言状态；
6. 相关系列。

超过约二十篇的系列需要分组、折叠或小目录；不能只把卡片继续向下堆叠。科幻区的六个问题分架可以作为大型书架的参考，但不同媒介不必机械复制同一套分组。

## 12. Article page 的统一结构

建议每篇文章增加以下上下文，不改变正文写法：

- 面包屑：`Explore > 方向 > 分类 > 系列 > 本篇`；
- 系列位置：`第 3 篇，共 8 篇`；
- 首次发布与最后重要修订日期；
- 清楚稳定的语言切换；
- 上一篇／下一篇；
- 三个不同职责的后续入口：
  1. 系列下一篇；
  2. 同问题、不同系列；
  3. 跨领域但直觉相连的一篇；
- 返回系列和返回 Explore 的出口。

相关阅读不应完全自动按共同词频生成。机器可以提出候选，最终关系由编辑确认。

## 13. 多语言模型

八种语言：English、简体中文、繁體中文、日本語、Français、Deutsch、Español、한국어。

### 13.1 canonical 内容身份

每一篇内容拥有一个不随语言变化的 `content_id`。语言版本是该身份下的 edition：

```text
content_id: everyday.relationships.01
canonical_url: /essays/everyday/relationships/01-when-care-becomes-control.html
editions:
  en: same-page
  zh-Hans: same-page
  zh-Hant: same-page-or-dictionary
  ja: /essays/everyday/relationships/ja/01-when-care-becomes-control.html
  fr: /essays/everyday/relationships/fr/01-when-care-becomes-control.html
  de: /essays/everyday/relationships/de/01-when-care-becomes-control.html
  es: /essays/everyday/relationships/es/01-when-care-becomes-control.html
  ko: /essays/everyday/relationships/ko/01-when-care-becomes-control.html
```

上例只是模型说明；实际 URL 以逐页审计结果为准。

### 13.2 语言体验规则

- 搜索结果进入页面后必须落在读者搜索时使用的语言；
- 同一站内继续阅读时保持当前语言；
- 若下一篇没有当前语言，明确提示可用语言，不静默切回英文或中文；
- 语言频道首页展示适用于该语言的 Start Here、Latest 和 Explore，而不是只列已经翻译的系列；
- 新增翻译更新可在语言频道的 Latest 中突出，在全站 Latest 中合并显示。

## 14. 内容注册表

在改 Search 和 Latest 以前，建立一个机器可读、人工可审计的单一事实源。建议至少包含：

```json
{
  "content_id": "science-fiction.solaris.01",
  "record_type": "essay",
  "canonical_url": "/essays/science-fiction/solaris/1-what-we-seek-in-space.html",
  "primary_domain": "stories",
  "category": "science-fiction",
  "series": "solaris",
  "sequence": 1,
  "titles": {
    "en": "No One Comes to Meet Him",
    "zh-Hans": "没有人来接他",
    "zh-Hant": "沒有人來接他"
  },
  "published_at": "2026-09-03",
  "updated_at": null,
  "update_kind": "new",
  "editions": {},
  "tags": [],
  "entry_level": "general",
  "featured": false,
  "index_status": "public"
}
```

实施时不建议手工一次录入七千多个 HTML 页面。先写只读扫描器提取 title、description、canonical、`html lang`、可见日期和目录关系，生成候选表；然后人工处理异常和 canonical 合并。

内容注册表建成后，应反向生成：

- Latest；
- Library 数量；
- 搜索过滤数据；
- 系列语言状态；
- sitemap；
- 基础链接审计报告。

## 15. URL 与兼容规则

1. 已公开 canonical URL 默认永久保留；
2. 展示分类变化不触发目录搬迁；
3. 重复作品合并时保留质量更高的版本，旧 URL 使用明确重定向；
4. 不以 JavaScript 跳转替代服务器／托管层可识别的永久重定向，除非部署条件确实不允许；
5. 查询参数可用于传递阅读语言，但不能改变 canonical 内容身份；
6. 每一批上线前比较旧、新 sitemap，并检查意外消失的 URL；
7. 外部来源已经引用的深层链接必须继续可达。

## 16. 分批实施路线

### Batch 0：蓝图与冻结线

- 完成本文件；
- 暂缓新增 category、批量新系列和新一轮全语言拓展；
- 正文修订、事实更正与断链修复仍可继续。

验收：双方同意页面职责、五扇门与 URL 原则。

### Batch 1：内容注册表原型

- 编写只读扫描器；
- 先覆盖 root 页面、13 个 Library 大类和 10 个代表系列；
- 输出异常报告，不改现有 HTML；
- 确认 canonical、日期和语言映射模型能覆盖旧式与新式页面。

验收：代表样本能够生成准确的 Explore、Latest 和语言状态数据。

### Batch 2：导航与首页线框

- 先做静态原型，不替换线上首页；
- 验证桌面与手机顶栏；
- 验证五扇门、Latest 六项与阅读路径的视觉优先级。

验收：新读者无需理解目录即可选择下一步，移动端不出现横向溢出。

### Batch 3：Explore 与新 Home

- 上线 Explore；
- 将首页从完整目录改为接待厅；
- Library 保持旧 URL 和完整入口；
- 暂不同时上线 Search，降低单批风险。

验收：所有当前 Library 大类都可在三次选择以内到达；旧深层链接不变。

### Batch 4：Latest

- 上线事件模型和日期归档；
- 首页接入最近六项；
- 区分新作、修订和语言扩展。

验收：抽查最近二十项与真实发布历史一致；八语版本不重复刷屏。

### Batch 5：Search

- 建立当前语言搜索；
- 加入四个核心筛选；
- 处理英／简／繁同页索引；
- 进行中日韩分词和重音字符测试。

验收：用人物名、作品名、日常问题、SAE 术语和不同语言各做测试；无错误语言落地。

### Batch 6：系列页与文章页上下文

- 先选择三种规模的样本：短系列、30 篇系列、百部以上大型书架；
- 稳定后逐类推广面包屑、进度和相关阅读。

验收：读者从任意搜索结果进入后，都能理解位置并继续前进。

### Batch 7：八语频道统一与清理

- 补齐各语言的 Home／Start Here／Explore／Latest／Search 入口；
- 清理重复入口和已确认的遗留页；
- 更新 sitemap 与结构化元数据。

验收：八种语言按同一信息架构运行，同时允许内容覆盖率不同。

## 17. 全程验收指标

不必一开始引入复杂分析平台。每批先用可验证的结构指标：

- 新读者从 Home 一次点击可进入 Start Here、Explore、Latest 或 Search；
- 任意公开文章都能追溯到一个系列和一个 Explore 方向；
- 任意文章至多三层回到完整主题地图；
- Search 默认不混入错误语言；
- Latest 不把同一文章的语言版本当成多篇新作；
- 页面在手机端无导航溢出；
- 旧 URL 和 canonical 不因展示重组而变化；
- 系列篇数、语言数和 sitemap 由同一数据源生成。

若未来加入尊重隐私的访问统计，最值得观察的是：

- 首页五扇门的进入比例；
- Search 无结果词；
- 文章读完后的下一步点击；
- Start Here 到阅读路径的继续率；
- 回访读者对 Latest 的使用率。

## 18. 本轮明确不做

- 不重写正文；
- 不重新设计品牌视觉；
- 不更换域名或批量改 URL；
- 不用算法自动生成全部相关推荐；
- 不追求所有语言在同一天拥有完全相同的内容；
- 不把数学、物理、热力学材料并入这个散文与哲学站点；
- 不在内容注册表完成前仓促上线全站搜索。
